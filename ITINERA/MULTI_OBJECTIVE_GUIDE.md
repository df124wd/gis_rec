### 2. 推荐的算法

#### 方案1：帕累托前沿（Pareto Front）⭐ **最推荐**

**优点**：
- ✅ 简单直观，易于理解和解释
- ✅ 不需要预先设定权重
- ✅ 适合小数据集（39条完全够用）
- ✅ 计算复杂度低：O(n²m)，n=候选数，m=目标数
- ✅ 提供多样化的推荐结果

**算法原理**：
```
帕累托支配关系：
- 候选A支配候选B = A在所有目标上不差于B，且至少一个目标更好
- 帕累托前沿 = 所有不被其他候选支配的候选集合

示例：
候选A: 交通9分, 价格0.2万/㎡, 面积30000㎡
候选B: 交通7分, 价格0.15万/㎡, 面积35000㎡
候选C: 交通5分, 价格0.1万/㎡, 面积40000㎡

→ A、B、C都在帕累托前沿（无法同时改进所有目标）
```

**实现**：已创建 `model/multi_objective.py`

**优点**：
- ✅ 实现简单

**缺点**：

- ❌ 计算开销大
- ❌ 对于39条数据过度工程化

**建议**：不推荐，你的数据量用帕累托前沿足够

### 3. 多目标优化的应用场景

#### 场景1：交通 vs 价格（最常见）

```
用户需求："交通便利且价格便宜的工业用地"

冲突：交通好的地块通常价格高

多目标优化输出：
┌─────────┬─────────┬─────────┐

├─────────┼─────────┼─────────┤

│ C（便宜）│ 5.0分   │ 0.12万  │ ← 价格最优
└─────────┴─────────┴─────────┘

→ 用户可根据预算选择
```

#### 场景2：面积 vs 总价

```
用户需求："大面积且总价不超过5000万"

冲突：面积大的地块总价高

多目标优化输出：
┌─────────┬─────────┬─────────┐
│ 地块    │ 面积    │ 总价    │
├─────────┼─────────┼─────────┤
│ A       │ 40000㎡ │ 6000万  │ ← 超预算
│ B       │ 30000㎡ │ 4500万  │ ← 符合约束
│ C       │ 20000㎡ │ 3000万  │ ← 面积小
└─────────┴─────────┴─────────┘

→ 帕累托前沿：B和C都是最优解
```

#### 场景3：三目标优化

```
用户需求："花都区食品厂，交通便利，面积大，价格低"

冲突：三个目标无法同时最优

多目标优化输出（帕累托前沿）：
┌─────────┬─────────┬─────────┬─────────┐
│ 地块    │ 交通分  │ 面积    │ 价格    │
├─────────┼─────────┼─────────┼─────────┤
│ A       │ 8.0分   │ 40000㎡ │ 0.18万  │ ← 交通+面积优
│ B       │ 6.0分   │ 35000㎡ │ 0.15万  │ ← 平衡
│ C       │ 9.0分   │ 25000㎡ │ 0.25万  │ ← 交通最优
│ D       │ 5.0分   │ 45000㎡ │ 0.12万  │ ← 面积+价格优
└─────────┴─────────┴─────────┴─────────┘

→ 没有一个候选被其他候选完全支配
→ 提供4种不同侧重的选择
```

def recommendations():
    data = request.get_json(force=True)
    requirements = data.get('requirements', '').strip()
    top_k = int(data.get('top_k', 10))
    use_pareto = data.get('use_pareto', True)  # 新增参数

            {'name': '价格_万元/㎡', 'maximize': False},

        optimizer = MultiObjectiveOptimizer(selector.site_data)
        candidate_ids = req_topk_sites[:, 0].astype(int).tolist()
        pareto_indices = optimizer.pareto_front(objectives, candidate_ids)
        
        # 排序并取Top-K
        weights = selector.derive_scoring_weights()
        obj_weights = {
            '交通_便利评分(0-10)': weights.get('traffic', 0.34),
            '价格_万元/㎡': weights.get('price', 0.33),
            '宗地面积(平方米)': 0.1
        }
        ranked = optimizer.rank_pareto_front(pareto_indices, objectives, obj_weights)
        final_ids = [idx for idx, score in ranked[:top_k]]
    else:
        # 使用原始排序
        final_ids = req_topk_sites[:top_k, 0].astype(int).tolist()
    
    # 生成推荐报告
    recommendation = selector.generate_recommendation(final_ids, [])
    
    return jsonify(recommendation)

## 💡 常见问题

### Q1: 为什么帕累托前沿只有8个地块？

**A**: 这是正常的！帕累托前沿是**非支配解集**，只包含那些在某些目标上表现最优的地块。从39个候选中筛选出8个，说明：
- 其他31个地块被这8个地块支配（在所有目标上都不如这8个）
- 这8个地块各有优势，提供了多样化的选择

### Q2: 如何选择优化目标？

**A**: 根据用户需求动态选择：
- 强调"交通便利" → 加入交通目标
- 强调"价格便宜" → 加入价格目标
- 强调"面积大" → 加入面积目标
- 可以2-4个目标组合

### Q3: 权重如何设置？

**A**: 两种方式：
1. **自动推导**：使用 `derive_scoring_weights()` 从用户需求中提取
2. **用户指定**：前端提供滑块让用户调整

### Q4: 多目标优化会增加响应时间吗？

**A**: 几乎不会！
- 39条数据的帕累托计算 < 1ms
- 主要时间在LLM调用（3-5秒）
- 多目标优化的开销可以忽略
