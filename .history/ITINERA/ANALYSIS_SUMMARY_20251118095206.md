### ⚠️ 存在的问题

#### 🔴 严重问题

1. **过度工程化**
   ```
   问题：三层处理同一需求（语义检索 → 结构化过滤 → 需求覆盖）
   影响：代码复杂度高，维护成本大
   建议：简化为两层（语义检索 → 综合评分）
   ```

2. **缺少真正的多目标优化**
   ```
   问题：只是简单加权求和，无法处理冲突目标
   影响：推荐质量受限，无法满足复杂需求
   建议：添加帕累托多目标优化
   ```

#### 🟡 中等问题

3. **权重推导不够智能**
   ```
   问题：硬编码规则，覆盖有限
   影响：权重不贴合用户意图
   建议：使用LLM智能推导权重
   ```

4. **缺少交互式调整**
   ```
   问题：用户无法调整权重或约束
   影响：推荐结果不可控
   建议：添加前端权重滑块
   ```

5. **可解释性不足**
   ```
   问题：只有LLM生成的优势/风险，缺少分数解释
   影响：用户不理解为什么推荐这些地块
   建议：添加分数拆解和对比分析
   ```

## 优化建议（优先级排序）

### 🔥 高优先级（立即优化）

#### 1. 移除冗余功能
- `apply_struct_filters()` - 结构化约束过滤
- `blend_with_safe()` - SAFE融合
- `generate_site_order()` - TSP访问顺序
- 部分 `apply_request_overrides()` - 需求覆盖

**预期效果**：
- 代码量减少30%
- 响应速度提升20%
- 维护成本降低50%

#### 2. 简化评分逻辑
```python
# 当前（复杂）
final = w_vector * text_norm + w_poi * (w_comp * comp + w_struct * struct)

# 优化后（简洁）
final = w_text * text + w_traffic * traffic + w_price * price + w_region * region
```

**预期效果**：
- 逻辑清晰，易于理解
- 分数可解释性提升
- 便于调试和优化

### 🟠 中优先级（1-2周内）

#### 3. 添加多目标优化

```python
# 帕累托前沿
pareto_front = pareto_optimization(candidates, objectives)

```

**预期效果**：
- 提供多样化推荐
- 处理冲突目标（如"交通便利"vs"价格便宜"）

**预期效果**：
- 权重更贴合用户意图
- 减少硬编码规则
- 提升推荐准确性
