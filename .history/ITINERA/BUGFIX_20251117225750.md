# Bug修复说明

## 问题描述

启动服务时报错：
```
openai.BadRequestError: Error code: 400 - {'error': {'message': 'Model Not Exist', 'type': 'invalid_request_error'}}
```

## 根本原因

1. **配置冲突**：`config/app_config.json` 中设置了 `"OPENAI_CHAT_MODEL": "deepseek-chat"`
2. **硬编码模型**：`site_selector.py` 中硬编码了 `self.MODEL = "gpt-4o"`
3. **环境变量优先级**：代码中 `os.getenv("OPENAI_CHAT_MODEL")` 会读取配置文件的值，导致向DeepSeek API发送了错误的模型名称

## 修复内容

### 1. 移除配置文件中的模型名称设置
```json
// 修复前
{
  "OPENAI_CHAT_MODEL": "deepseek-chat"  // ❌ 错误
}

// 修复后
{
  // ✅ 移除此配置，让代码自动选择
}
```

### 2. 修改 `proxy_call.py` 的模型选择逻辑
```python
# 修复前
model = os.getenv("OPENAI_CHAT_MODEL") or self.default_chat_model  # ❌ 会读取错误配置

# 修复后
model = self.default_chat_model  # ✅ 直接使用provider的默认模型
```

### 3. 修改 `site_selector.py` 的模型设置
```python
# 修复前
self.MODEL = "gpt-4o"  # ❌ 硬编码OpenAI模型

# 修复后
self.MODEL = None  # ✅ None表示使用proxy的默认模型
```

## 修复后的行为

- **使用DeepSeek时**：自动使用 `deepseek-chat` 模型
- **使用OpenAI时**：自动使用 `gpt-3.5-turbo-1106` 模型
- **Embedding**：自动使用本地模型（`BAAI/bge-base-zh-v1.5`）

## 验证修复

重启服务，应该看到：
```
[LLM] 使用DeepSeek API (base_url=https://api.deepseek.com)
[Embedding] 加载本地模型: BAAI/bge-base-zh-v1.5
✓ 服务启动成功
```

测试推荐功能，应该正常工作。
